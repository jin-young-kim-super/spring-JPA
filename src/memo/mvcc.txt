MVCC의 정의 트랜잭션마다 자신이 봐야 하는 데이터 버전을 선택해서 읽는다
-> MVCC는 데이터 변경 시 이전 버전을 Undo Log 등에 보관하고, 각 트랜잭션이 자신의 【격리 수준(Isolation Level】)에 맞는 데이터 버전을 선택해서 읽도록 하는 
데이터베이스 동시성 제어 기법이다(즉, 개발자가 설정한 각 격리 레벨에서 보장하는 오페레이션 에러 오류를 방지를 보장하는 격리 레벨 기술의 핵심 구현(메카니즘))

・UNdo Log의 데이터 저장 흐름
EX)

MEMBER
id | age
---------
1  | 20


Transaction A
BEGIN;

UPDATE MEMBER
SET age = 30
WHERE id = 1;

DB 내부:
현재 데이터
age = 30

Undo Log
age = 20 // 30이 아니라 20이 저장됨에 주의! 다른 트랙잭션들은 이 시점에 AGE=20을 읽어 들인다.

아직:
COMMIT ❌

Transaction B
SELECT age
FROM MEMBER
WHERE id = 1;

MVCC 판단:
현재 데이터 age=30
↓
하지만 A는 아직 커밋하지 않음
↓
A의 변경은 보이면 안 됨
↓
Undo Log 사용

결과:
age = 20

그런데 A가 롤백한다면?

A:

ROLLBACK;

그러면 DB는:

Undo Log를 사용해서:

현재 데이터

age = 30
     ↓
age = 20으로 복구한다.

최종 상태:
MEMBER
age = 20
그럼 B가 읽은 값은?

B:
age = 20이다.
현재 DB 상태도: age = 20이다.
즉: B가 읽은 값 = 최종 커밋된 값이다. 전혀 문제가 없다.(격리 레벨에서 보장해야 하는 Dirty Read 방지 보장)


정리 : MVCC는 트랜잭션 격리 수준을 구현하기 위한 핵심 메커니즘이고, 최종적으로 어떤 수준의 일관성을 제공할지는 개발자의 Isolation Level과 Lock 전략이 결정한다.
-> 이러한 이유 때문에 개발자는 도메인의 비즈니스 규칙을 분석하고, 그 규칙을 만족하기 위해 적절한 트랜잭션 경계, Isolation Level, Lock 전략, 애플리케이션 제어 방식을 선택해야 한다.
