엔티티 매핑은 사실상 JPA 설계이다. 
즉,  관계형 데이터 베이스 설계를 유지하면서 애플리케이션 코드의 객체 지향성은 전혀 떨어 뜨리지 않게 @Id, @OneToMany 등의 에노테이션을 통해 실현을 시키는 설계이다. 
ex)
・객체와 테이블을 어떻게 매핑하나 : @Entity, @Table
・데이터 베이스 스키마를 어떻게 생성하냐 : @Column
・필드와 컬럼 매핑을 어떻게 하냐 : @Id
・기본 키 매핑 : @ManyToOne, @OneToMany, @JoinColumn 등

@Entity
-> 테이블과 매핑시킬 클래스에는 반드시 @Entity를 붙여야 한다.

주의점(JPA 스펙)
1. 기본 생성자 필수 : 파라미터가 없는 public or protected 생성자여야 함
-> JPA에서도 동적으로 Proxy 객체 등을 만들어 주입할 일이 있는데 그때 기본 생성자가 필요하다

2. final 클래스, enum 클래스, 인터페이스, inner 클래스에는 @Entity 사용x

3. 엔티티 내의 필드(DB에 저장할 필드)에는 절대 final를 사용 x
-> 칼럼은 언제나 변경이 가능해야 하므로 당연한 이야기

@Entity 속성
1. name
-> name="member"로 JPQL에서 사용한 엔티티 명을 지정해 줄 수가 있다. 그러나 가급적 디폴트 모드를 사용하다
디폴트 모드는 @Entity가 붙은 클래스 명을 엔티티 명으로 한다.
그러나 만약에 다른 패키지에 똑같은 명의 클래스가 있다면 그때는 name을 사용해서 다른 이름으로 엔티티 명을 지정해주지만
되도록이면 다른 패키지에서 클래스 명의 중복이 없게 하자

@Table 속성
1. name
-> name="member"로 매핑한 테이블 명을 지정할 수가 있다. 기본값은 엔티티 명을 테이블 명으로 매핑을 한다
※ 강의자료에는 다른 속성들이 있지만 나중에 추후에 학습을 한다고 한다.

주의!!!
@Entity(name = "...") : JPQL에서 사용할 엔티티 이름
@Table(name = "...") :실제 데이터베이스 테이블 이름
